# P001 Epoch 90 — P0-A close-gate enforcement

## Problem

`tools/validate_run_records.py` already rejects a voluntary normal `CONTINUE` turn shorter than 10 minutes (600 seconds). However, that validator only protects records that are actually present in `state/RUNS.jsonl`. A runtime can therefore violate the intended gate operationally if it marks `CURRENT` as closed/checkpointed but fails to append a corresponding closed RUNS record.

This explains why policy text and validator logic can both be correct while short turns still appear in live operation: **the enforcement surface had an omission escape hatch**.

## Correction

Added a second, orthogonal gate:

- `tools/audit_latest_run_record.py@38570c26a4bd1f3b277fb88703c768dc6685f507`
  - if `CURRENT.run_state` is `CHECKPOINTED` or `HANDOFF_COMMITTED`, the current owner must have a matching closed record in `state/RUNS.jsonl`;
  - an absent record or an open-only record fails the audit;
  - an active run is not forced to fabricate a close record.
- `tests/test_audit_latest_run_record.py@1df00adb0af7dc7d2815a1cfb1c4e1d68b7ce6a5`
  - active run accepted;
  - closed run without record rejected;
  - open-only record rejected;
  - matching closed record accepted.
- `.github/workflows/audit-latest-run-record.yml@ef7d957d99548cd112ca26b1d3213cdf0b411aef`
  - validates all RUNS records;
  - audits the latest closed CURRENT owner;
  - runs both run-record and close-audit tests.

The run validator itself was also advanced to `DURABLE_FIRST_FINAL_FLUSH_V5_6` trace semantics in `tools/validate_run_records.py@d14ee89fc4fc6a5f2cbfa5bb0a0fba32839e0e34`, with regression coverage in `tests/test_run_records.py@3f1fc11c230372ed346f5aa5837687a904b5538b`.

## Decision

**ADOPT.** This is higher-value than adding more prose to the 600-second rule because it closes a concrete enforcement omission. It still does not prove P0-A pass: the live runtime must produce a normal `CONTINUE` sample with observed duration >=600 seconds. Scheduler mutation, state bookkeeping, and trace bookkeeping remain non-useful unless they materially implement/test the runtime itself.
